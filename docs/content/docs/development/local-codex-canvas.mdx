# 桌面助手连接画布原理

桌面版由 Electron 主进程统一启动网页服务、Canvas Agent、Codex app-server 和本地代理。Canvas Agent 是本机桥接层，负责把 Codex 的工具调用送到当前网页，再把网页执行结果返回给 Codex。

```txt
Electron 桌面壳
  ├─ Canvas Agent HTTP/SSE 服务
  │   └─ Codex app-server --stdio
  └─ 本地网页
      └─ React 画布状态
```

Canvas Agent 不是另一个负责推理的模型。Codex 负责理解任务、规划和调用工具；Canvas Agent 负责本机进程、协议和网页连接；浏览器负责真正修改画布状态。

## 右侧助手的调用链路

```txt
浏览器右侧助手
  -> Canvas Agent /agent/codex/turn
  -> Codex app-server --stdio
  -> 内部 infinite-canvas MCP
  -> Canvas Agent /api/tools
  -> SSE tool_call
  -> 浏览器 React 画布
  -> /canvas/result
  -> Codex
```

用户在网页右侧输入提示词后，Canvas Agent 会复用当前 Codex thread。Codex 通过内部 MCP 调用 `canvas_get_state`、`canvas_apply_ops`、`canvas_generate_image` 等工具。工具请求由 Canvas Agent 转发到当前网页，网页执行后回传结果。

`mcp` 进程只是 Codex app-server 使用的 stdio 协议适配器，不是用户需要单独启动的服务。普通 Canvas Agent 也不再作为独立 npm CLI 运行，只由桌面壳以 `desktop` 模式启动。

## 画布状态同步

浏览器会把当前画布快照发送给 Canvas Agent：

```txt
POST /agent-api/canvas/state
```

快照包含画布、节点、连线、选区和视口。Codex 读取画布时，读取的是 Canvas Agent 保存的最新快照，不会直接访问浏览器 DOM。

## 画布写操作

以创建文本节点为例：

```txt
Codex 调用 canvas_create_text_node
  -> MCP 转发到 Canvas Agent
  -> Canvas Agent 转换为 canvas_apply_ops
  -> SSE tool_call 发送到网页
  -> React 状态执行 add_node
  -> 网页 POST /canvas/result
  -> Canvas Agent 返回结果给 Codex
```

高级工具会转换成统一的画布操作，例如 `add_node`、`update_node`、`delete_node`、`connect_nodes`、`set_viewport` 和 `select_nodes`。网页可以在执行写操作前要求用户确认，并保存操作前快照用于撤销。

## 会话与日志

Codex 的 `threadId` 是一段可恢复的对话，`turnId` 是其中一次请求，`itemId` 是请求中的具体回复、计划、工具或命令事件。Canvas Agent 负责转发这些事件，并保存必要的补充历史和消息展示元数据。

桌面壳是唯一的文件日志出口。Canvas Agent、Codex app-server 和本地代理的输出统一写入：

```text
Windows: %APPDATA%\Infinite Canvas\desktop.log
Linux:   ~/.config/Infinite Canvas/desktop.log
```

Agent 不再创建独立的 `~/.infinite-canvas/logs/canvas-agent-*.log` 文件。

## 安全边界

- 桌面网页服务和 Canvas Agent 只监听本机回环地址。
- Canvas Agent 只接受 Electron 注入的桌面网页来源跨域请求。
- Codex 不直接访问浏览器 DOM，也不直接持有 React 画布状态。
- 画布写操作最终由浏览器执行，因此可以在网页侧做确认和撤销。
- Agent、Codex 和 MCP 的连接由桌面壳管理，用户不需要填写 Agent 地址、token 或手动注册 MCP。

一句话概括：

```txt
Codex 负责思考，Canvas Agent 负责本机桥接，浏览器负责执行画布操作。
```
